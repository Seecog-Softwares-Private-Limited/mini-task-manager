Webhook Reliability/PAY-198

Webhook retries duplicate charge events

AttachSubtaskLinkCreate branchSummarise thread

When the processor responds slowly (>8s), the retry scheduler fires a second webhook before the first ack. Merchants see two charge.succeeded events and some auto-fulfil the order twice.

Fix: unique index on event_id, short-circuit the retry if the event was already acknowledged, backfill 30 days.
