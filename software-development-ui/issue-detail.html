PAY-198 · Bug

Webhook retries duplicate charge events

When the downstream processor responds slowly (>8s), our retry scheduler fires a second webhook before the first ack lands — merchants see two charge.succeeded events for the same payment intent. Need an idempotency guard keyed on event_id before re-queuing.
